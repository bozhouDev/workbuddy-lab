上一篇的飞书是官方做好的连接器，点 `+` 就能装。但总有你要的服务不在列表里：公司内部的查询系统、某个行业数据网站、你自己写的小工具……这时候就用连接器页右上角的 **自定义连接器**，自己接一个。

连接器的本质叫 **MCP**（可以理解成 AI 的 Type-C 接口）。只要按这个标准做一个「插头」，WorkBuddy 就能插上用。

## 先看一个翻车：它会编天气

不接任何数据，直接问「明天上海会下雨吗？要不要带伞？」，它多半会很自然地回答「多云转小雨，降水概率 40% 左右，建议带伞」。展开执行步骤一看：**没调用任何工具**。这个 40% 是编的。

天气、汇率、库存、快递这种**每时每刻在变的数据**，它自己是不知道的，必须给它接一根数据线。下面就做一个天气连接器，用 [Open-Meteo](https://open-meteo.com/) 的免费接口，**不用注册、不要 Key**，最适合练手。

## MCP 从哪来：三个来源

| 来源 | 怎么接 | 适合 |
| --- | --- | --- |
| 让 WorkBuddy 帮你写 | 说清需求，它写好代码并告诉你怎么填 | 新手首选，今天要做的 |
| GitHub 上开源的 MCP | 按项目说明填启动命令 | 别人已经做好的常见服务 |
| 服务商给的远程地址 | 传输类型选远程，填 URL | 服务商官方提供了 MCP 地址 |

## 第 1 步：让 WorkBuddy 写一个天气 MCP

新建任务，选好分组（比如 `WorkBuddy-练习`），发这段话：

```text
帮我写一个查天气的 MCP 服务（Node.js），用 Open-Meteo 免费接口，不需要 Key；
只提供一个工具 get_forecast：输入城市名，返回未来 3 天的最高最低温和降水概率；
放在当前分组的 weather-mcp 文件夹；
写好后自测一次，再告诉我在 WorkBuddy 里怎么填。
```

注意这段话说清了三件事：**输入什么**（城市名）、**返回什么**（3 天的温度和降水概率）、**要不要 Key**（不要）。自己做任何连接器，说清这三件事就够了。

它会建好文件夹、装好依赖、自测一次，然后给你一张填写表。核心代码大概长这样（用 `@modelcontextprotocol/sdk` 1.17.0 + `zod` 3 实测能跑通）：

```bash
# 在 weather-mcp 文件夹里装依赖：zod 要用 3.x，装成 4.x 时工具参数会丢失、调用报错
npm install @modelcontextprotocol/sdk@1.17.0 zod@3
```

```js
// server.js：天气 MCP，只提供一个工具 get_forecast
// package.json 里需要 "type": "module"，依赖 @modelcontextprotocol/sdk 和 zod
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { z } from 'zod';

const server = new McpServer({ name: 'my-weather', version: '1.0.0' });

// 城市名 → 经纬度
async function geocode(city) {
  const url = `https://geocoding-api.open-meteo.com/v1/search?name=${encodeURIComponent(city)}&count=1&language=zh`;
  const data = await (await fetch(url)).json();
  if (!data.results?.length) throw new Error(`找不到城市：${city}`);
  return data.results[0];
}

server.tool(
  'get_forecast',
  '查询某个城市未来 3 天的天气、最高最低温和降水概率',
  { city: z.string().describe('城市名，例如：上海') },
  async ({ city }) => {
    const place = await geocode(city);
    const url =
      `https://api.open-meteo.com/v1/forecast?latitude=${place.latitude}&longitude=${place.longitude}` +
      '&daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max' +
      '&timezone=Asia%2FShanghai&forecast_days=3';
    const d = (await (await fetch(url)).json()).daily;
    const lines = d.time.map(
      (t, i) => `${t}  ${d.temperature_2m_min[i]}~${d.temperature_2m_max[i]}°C  降水概率 ${d.precipitation_probability_max[i]}%`,
    );
    return { content: [{ type: 'text', text: `${place.name}（数据来源 Open-Meteo）\n${lines.join('\n')}` }] };
  },
);

// 通过标准输入输出（stdio）和 WorkBuddy 对话
await server.connect(new StdioServerTransport());
```

你不用看懂每一行，知道三处就行：`server.tool` 定义了一个工具、`{ city: ... }` 是输入、`return` 的是返回给 AI 的文字。

## 第 2 步：添加到「自定义连接器」

进 **专家·技能·连接器** → **连接器**，点右上角 **自定义连接器**，弹出「添加 MCP 服务器」表单。按 AI 给的填写表填：

| 字段 | 填什么 |
| --- | --- |
| 名称 | `my-weather` |
| 传输类型 | 本地命令（程序在你电脑上跑） |
| 启动命令 | `node` |
| 命令参数 | `server.js` 的**完整路径**（别写 `~/` 开头的简写，启动时不认），比如 `/Users/你的用户名/WorkBuddy-练习/weather-mcp/server.js`（Windows 是 `C:\Users\...\server.js`） |
| 环境变量 | 不用填 |

如果服务商给的是一个网址，传输类型就选远程那一种，填服务器 URL。表单也支持直接编辑 JSON，写法和大多数 MCP 客户端一样：

```json
{
  "mcpServers": {
    "my-weather": {
      "command": "node",
      "args": ["/Users/你的用户名/WorkBuddy-练习/weather-mcp/server.js"]
    }
  }
}
```

<Warning title="Key 只放在环境变量里">
  今天的天气接口不要 Key。以后接需要 Key 的服务，<strong>Key 只填在你自己 WorkBuddy 客户端里这张表单的「环境变量」里</strong>，不要写进提示词、技能或者发到对话里。
</Warning>

## 第 3 步：信任确认

点「添加」后，列表里会出现 `my-weather`，旁边写着「首次连接此 MCP 服务需要您的信任确认」，按钮是 **信任 / 拒绝**。

什么能点信任？**你自己写的、看过代码的、来源可靠的**（官方出的，或者大量人用过的开源项目）。「AI 帮你写的、自测通过」不等于可以信任，点之前核对三件事：**启动的是哪个文件、会访问哪些网址、要不要 Key 或读写别的文件**。这个天气例子：只启动 `server.js`、只访问 Open-Meteo 的两个接口、不要 Key，对得上再点。来路不明的别信：MCP 在你电脑上运行，**权限和你一样大**，能读你能读的文件。

信任后会显示「1/1 个工具已启用」。工具数要留心：一个连接器开几十个工具会让它挑花眼，用不到的可以关掉。

## 第 4 步：再问一次

回到首页，同样问「明天上海会下雨吗？要不要带伞？」。这次展开执行步骤，能看到 **调用 my-weather · get_forecast**，回答里的温度和降水概率都来自 Open-Meteo。

想让它回答更可靠，提示词里加一句「告诉我数据来源」，它就会注明。注意它只能说出工具真正返回的东西：这个工具只给温度和降水概率，问它「会不会转晴」它就只能推测，要判断晴雨得让工具多返回天气状况字段。

## 同样的套路还能接什么

只要说清「输入什么、返回什么、要不要 Key」，很多日常小事都能做成连接器：

- 查汇率：输入币种，返回最新汇率（找一个免费汇率接口）；
- 查公司内部系统：输入订单号，返回订单状态（需要内部接口地址，Key 放环境变量）；
- 读本地数据库：输入问题，返回查询结果（只开只读权限）。

## 一句话记住

**列表里没有就自己接：让 WorkBuddy 写 MCP 并说清输入、输出和 Key；添加时 Key 只放环境变量；只信任可靠来源，工具别开太多。**
