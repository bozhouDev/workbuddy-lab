第 2 章学会把任务说清楚以后，你会发现一个新麻烦：**同一类活，每次都要把那一大段要求重新打一遍**。整理群聊要交代五栏格式、不许编人名、只读原文件、文件名怎么起……哪天偷懒少说一句，结果就走样：格式变成一段话，没人认领的活被它安排给了某个同事，待确认事项直接漏掉。

这时候就该把这些要求**写成你自己的技能**。写一次，以后一句「整理成筹备纪要」就够了。

## 什么样的活值得做成技能

满足这三条再动手：

1. **会反复做**：每周、每次活动、每个客户都要来一遍；
2. **已经手动做顺了**：你知道「好」长什么样，也踩过几个坑；
3. **要求说得清**：格式、步骤、不许干的事都能写成一条条规矩。

还没做顺的活别急着做成技能，**一套没调好的要求写成技能，只会让它每次都按同样的方式出错**。

## 第 1 步：用「创建技能」让它起草

进左侧 **专家·技能·连接器** → **技能**，点右上角 **添加技能**，菜单里有三项：

| 选项 | 干什么 | 适合 |
| --- | --- | --- |
| 查找技能 | 让它去技能市场帮你搜一个并装上 | 不确定有没有现成的 |
| 上传技能 | 导入一个文件夹或 zip，里面必须有 `SKILL.md` | 别人做好发给你的技能 |
| 创建技能 | 让它根据你的描述写一个新技能 | 今天要学的 |

点 **创建技能**，会回到首页，输入框里预填了一句「请帮我创建一个可以实现「……」的skill」。**引号里填这个技能干什么**，后面把你平时反复交代的要求接上。比如：

```text
请帮我创建一个可以实现「把群聊记录整理成活动筹备纪要」的skill：
1. 固定输出 时间 / 地点 / 预算 / 分工 / 待确认 五栏；
2. 原文没写明的标“未明确”，不许自己补人名和金额；
3. 只读原文件，不改动；
4. 文件名用「活动名_筹备纪要.md」。
```

发出去以后，它会写好 `SKILL.md` 并装到 **已安装 → 用户自定义** 分组里。

## 第 2 步：检查 SKILL.md 的三处

技能的核心就是一个 `SKILL.md` 文件，开头两行最重要：

```markdown
---
name: 群聊整理成筹备纪要
description: 当用户要把群聊或会议记录整理成活动筹备纪要时使用
---

## 步骤
1. 只读取用户 @ 的群聊文件，不改动原文件
2. 按 时间 / 地点 / 预算 / 分工 / 待确认 五栏输出
3. 文件名：活动名_筹备纪要.md

## 禁止事项
- 原文没写明的一律标“未明确”，不许补人名和金额
- 不删除、不覆盖任何已有文件
```

- **name**：技能的名字，在 `/` 列表里看到的就是它。
- **description**：决定它**什么时候想起来用这个技能**。写成「当用户要……时使用」，你没点名时它也能自动认出来；写成「整理工具」这种空话，它就永远想不起来。这是最常见、也最隐蔽的坑。
- **禁止事项**：把你踩过的坑写死在这里，以后就不会再犯。

哪里不满意，直接在对话里说：「请帮我编辑 群聊整理成筹备纪要 这个 skill：……」。

## 第 3 步：开新对话测一次

新建一个任务，在输入框里打 `/`，你做的技能会出现在列表里。选它，@ 群聊文件，**用最偷懒的说法测**：

```text
@周末读书会群聊.txt 整理成筹备纪要。
```

如果五栏齐全、没写明的都标了「未明确」、文件名也对，这个技能就能用了。测的时候多换几份不同的群聊，看它会不会在某种情况下走样，走样了就回去改 `SKILL.md`。

<Warning title="做技能的两条红线">
  <ol>
    <li><strong>技能里别写密码、API Key、个人隐私</strong>：技能是可以打包分享的，写进去就等于跟着一起发出去了。需要密钥的服务，用连接器的「环境变量」。</li>
    <li><strong>别做「什么都管」的技能</strong>：一个技能只干一类活。什么都往里塞，description 写不清，它反而想不起来用。</li>
  </ol>
</Warning>

## 分享给别人

做好的技能在本地技能目录里是一个文件夹。把它打包成 zip 发给同事，对方在 **添加技能 → 上传技能** 里导入就能用。上传时会做安全检查，包含高风险操作的技能会被拦下。

## 一句话记住

**先手动做顺，再用「创建技能」把要求说全；重点检查 description 写成「当用户要……时使用」，最后开新对话用 `/` 测一遍。**
